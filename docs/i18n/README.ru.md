## Обзор

Руткиты в виде загружаемых модулей ядра (LKM) в Linux и их аналоги — расширения ядра — в macOS работают с теми же привилегиями, что и сама операционная система. Они могут подменять то, что ядро сообщает любой другой программе, включая `lsmod`, `ps`, `netstat` и `ls` — инструменты, которыми администратор пользуется в первую очередь на подозрительной машине.

Подход Redoubt структурный, а не основанный на списке сигнатур. Чтобы скрыться, руткит должен согласованно лгать по *каждому* пути, которым ядро отвечает на один и тот же вопрос; защитнику достаточно, чтобы правду сказал хотя бы один из них. Поэтому Redoubt собирает каждый факт как минимум двумя независимыми путями — модуль через `/proc/modules`, `/sys/module` и карту исполняемой памяти ядра; процесс через список libc, «сырой» системный вызов `getdents64` и проверку `kill(pid, 0)`; порт через `/proc/net/*` и `bind()` — и сообщает о расхождениях.

> **Прежде чем доверять вердикту `CLEAN`, прочитайте [docs/THREAT_MODEL.md](../THREAT_MODEL.md) (на английском).**

## Основные возможности

- **Обнаружение сопоставлением представлений, а не сигнатурами.** Поведенческие проверки продолжают работать, даже если руткит переименован.
- **16 проверок:** сокрытие модулей, целостность кода ядра (таблица системных вызовов, ftrace, встроенные хуки), скрытые процессы/порты/файлы, внедрение через динамический компоновщик и расширения ядра macOS.
- **Откалиброванные находки.** Каждая находка содержит уровень уверенности (0–100), идентификатор MITRE ATT&CK и конкретный следующий шаг; вердикт учитывает *независимые* проверки.
- **Учёт гонок.** Всё, что может измениться во время сканирования (процессы, модули, сокеты), перед отчётом повторно опрашивается и перепроверяется.
- **Честное покрытие.** Проверка, которую не удалось выполнить, отображается как *skipped* с причиной; `CLEAN` указывает, сколько проверок он охватывает.
- **Работает офлайн.** `snapshot` сохраняет все представления ядра; `--from` позже анализирует их на любой машине; `--baseline` сравнивает с заведомо чистым состоянием.
- **Ноль зависимостей.** C11 и `make`. Только чтение: без демона, без закрепления в системе, без автоматического «лечения».
- **Проверено на настоящем ядре.** CI при каждом коммите сканирует немодифицированное ядро Linux 6.17 и завершает сборку ошибкой, если результат не `CLEAN` при полном покрытии.

## Быстрый старт

```bash
git clone https://github.com/tejgokani/redoubt.git
cd redoubt
make                      # builds ./redoubt
make test                 # 88 unit assertions + 10 scenarios

./redoubt demo            # replay bundled rootkit scenarios (offline, no root)
sudo ./redoubt scan       # scan THIS machine (root = full coverage on Linux)
```

`./redoubt demo` и `make test` не требуют ни root, ни определённого ядра; сборщики данных macOS работают нативно. Сценарий презентации: [docs/DEMO.md](../DEMO.md) (на английском).

## Использование

| Команда | Что делает |
|---|---|
| `scan` | Сканирует эту машину (команда по умолчанию). |
| `demo [name\|all]` | Воспроизводит встроенный сценарий офлайн через настоящий движок обнаружения. |
| `eval [dir]` | Запускает все сценарии и выводит матрицу обнаружения (пройден/не пройден). |
| `snapshot DIR` | Сохраняет все представления ядра этой машины как доказательства или базовую линию. |
| `list-checks` | Перечисляет 16 проверок и то, что сравнивает каждая. |

| Параметр | Что делает |
|---|---|
| `--from DIR` | Анализировать каталог снимка/сценария вместо работающей системы. |
| `--baseline DIR` | Дополнительно сравнить с заведомо чистым снимком. |
| `--only a,b / --skip a,b` | Запустить или пропустить отдельные проверки по id. |
| `--fail-on SEV` | Код завершения `1`, если обнаружение не ниже этого уровня (`info`…`critical`, по умолчанию `medium`). |
| `--json` | Отчёт в машиночитаемом виде. |
| `--simulate SPEC` | Внести в живые данные «ложь руткита» для демонстрации ([docs/DEMO.md](../DEMO.md)). |

**Код завершения:** `0` ничего не найдено · `1` обнаружение · `2` ошибка использования или внутренняя · `3` неполное покрытие при `--strict-coverage`. Полный список: `redoubt --help`.

```bash
sudo ./redoubt snapshot /var/tmp/evidence      # снять представления с подозрительного хоста
./redoubt scan --from /var/tmp/evidence        # проанализировать позже на любой машине
```

## Что обнаруживает

16 проверок охватывают сокрытие модулей, хуки ядра, скрытые процессы/порты/файлы, внедрение через динамический компоновщик и расширения ядра macOS. Каждая сопоставляет указанные независимые источники:

| Проверка | Сопоставляемые источники |
|---|---|
| `mod-xview` | `/proc/modules` &harr; `/sys/module` &harr; `kallsyms` |
| `mod-orphan-mem` | vmalloc &harr; `kallsyms` &harr; `/sys/module/<name>/sections` |
| `mod-taint` | taint &harr; `dmesg` &harr; module views |
| `mod-provenance` | `/proc/modules` &harr; `modules.dep` |
| `syscall-table` | `sys_call_table` (`/proc/kcore`) &harr; `_stext`..`_etext` |
| `ftrace-hooks` | `enabled_functions` &harr; module lists |
| `inline-hooks` | `getdents` / `filldir` / `tcp4_seq_show` &hellip; prologues |
| `proc-xview` | `readdir` / `libproc` &harr; `getdents64` / `sysctl` &harr; `kill(pid, 0)` |
| `net-xview` | `/proc/net/*` &harr; `bind()` |
| `fs-xview` | `readdir()` &harr; `st_nlink` / `stat()` |
| `preload` | `ld.so.preload`, `LD_PRELOAD`, `DYLD_INSERT_LIBRARIES` |
| `known-iocs` | Diamorphine, Reptile, Adore, KBeast, Singularity, KoviD &hellip; |
| `kext-inventory` | `kmutil` &harr; IOKit &harr; `/Library/Extensions` |
| `boot-integrity` | `kern.bootargs` |
| `baseline` | `--baseline` |
| `hardening` | `sysctl`, lockdown, module signing, SIP |

## Доказательства

- **Настоящее ядро Linux при каждом коммите.** CI запускает `sudo redoubt scan` на немодифицированном ядре Ubuntu 6.17 и падает, если вердикт не `CLEAN` при выполнении всех 13 применимых проверок. По пути были найдены три настоящих ложных срабатывания; каждое теперь — регрессионный тест.
- **Настоящее сокрытие вживую на macOS.** `make hooks` собирает минимальный хук в пользовательском пространстве, скрывающий работающий процесс от `proc_listpids`; Redoubt обнаруживает его на живой машине.
- **Матрица сценариев и модульные тесты.** `make test` выполняет 88 проверок и 10 сценариев (6 смоделированных руткитов и 4 чистых/ложных контрольных).

Полное описание, включая то, что *не доказано*: [docs/EVALUATION.md](../EVALUATION.md) (на английском).

## Ограничения

Указаны сразу, потому что ложное чувство безопасности хуже, чем его отсутствие:

- **Это локальный инструмент пользовательского пространства.** Руткит, согласованно лгущий по всем путям, которые читает Redoubt, для него невидим. Решить это может только внешний взгляд (образ памяти от гипервизора или диск, прочитанный с другой машины).
- **Шесть сценариев руткитов смоделированы** по публичной документации, а не сняты с реальных заражений. Проверка на настоящем ядре показывает, что инструмент не даёт ложных тревог; она не доказывает обнаружение реального скрытого модуля ядра.
- **Для полного покрытия в Linux нужен root.** Без него часть проверок отображается как *skipped*. Блокировка ядра (lockdown) также может ограничивать `/proc/kcore`.
- **Часть проверок — эвристики,** и их уверенность соответственно ограничена (например, сокет, для которого вызван `bind()`, но не `listen()`, выглядит как скрытый порт).
- **Проверено только** на Ubuntu (ядро 6.17, x86_64) и macOS 26 на Apple silicon.
